## 주요 기능 {#features-at-a-glance}

VitePress 기본 테마는 라벨을 하나하나 번역하기 전까지 인터페이스를 영어로 보여 줍니다. VitePress I18n은 지정한 언어마다 이 라벨을 채워 넣기 때문에, 일본어 페이지 끝에 영어로 된 "Next page" 링크가 남지 않습니다.

<div class="home-feature-list">

- **13개 언어 기본 제공** 영어, 한국어, 중국어 간체와 번체, 일본어, 스페인어, 포르투갈어, 러시아어, 인도네시아어, 독일어, 프랑스어, 베트남어, 이탈리아어를 지원합니다.
- **함수 하나로 설정** 기존 설정을 `withI18n`으로 감싸면 끝납니다. 따로 만들거나 맞춰 둘 번역 파일이 없습니다.
- **검색도 번역** 로컬 검색과 Algolia DocSearch의 버튼, 검색 창, 결과 없음 문구를 언어마다 바꿔 줍니다.
- **직접 쓴 문구가 우선** `label`이나 언어별 `themeConfig`를 지정하면 그 언어의 기본 번역 대신 지정한 문구를 씁니다. `title`, `description`, `head`도 언어마다 다르게 둘 수 있습니다.
- **어떤 폴더 구조든 가능** `eng`, `kor` 같은 폴더를 `{ path, locale }`로 언어 코드에 연결하면 지금 쓰는 URL을 그대로 둘 수 있습니다.
- **`lang`과 언어 이름 자동 설정** 언어마다 `ko-KR` 같은 `lang` 속성과 언어 메뉴에 표시할 고유 이름을 넣어 줍니다.
- **의존성 없음** 런타임 의존성이 없는 작은 ESM 패키지입니다. VitePress가 설정을 읽을 때 한 번 실행됩니다.
- **TypeScript 타입 제공** `VitePressI18nOptions`와 `I18nLocale` 타입을 `vitepress-i18n/types`에서 가져올 수 있습니다.

</div>

## 설정 하나로 모든 언어에 {#from-one-config-to-every-language}

VitePress 옵션과 필요한 언어 코드를 넘기세요. `withI18n`이 돌려주는 설정의 `locales`에는 번역된 인터페이스 문구가 이미 들어 있고, VitePress는 해당 언어의 모든 페이지에 이 문구를 씁니다.

<div class="home-demo">
<div>

### 설정 파일 {#your-config}

```js
// .vitepress/config.mjs
import { defineConfig } from 'vitepress';
import { withI18n } from 'vitepress-i18n';

const vitePressOptions = {
  title: 'My Docs',
  lastUpdated: true,
  themeConfig: {
    editLink: {
      pattern: 'https://example.com/edit/:path'
    }
  }
};

export default defineConfig(
  withI18n(vitePressOptions, {
    // Any of the 13 supported language codes
    locales: ['en', 'ko', 'ja'],
    searchProvider: 'local'
  })
);
```

## 사용 사례 {#use-cases}

여러 언어로 문서를 내는 VitePress 사이트라면 어디에나 쓸 수 있습니다. 대표적인 구성은 다음과 같습니다.

<div class="home-use-cases">
<div class="home-use-case">

### 다국어 문서 사이트 {#multilingual-documentation-sites}

언어마다 폴더를 두고 언어 코드를 나열하세요. 내비게이션 라벨, 페이지 하단, 목차, 404 페이지가 각 폴더의 언어를 따릅니다.

[첫 언어 설정하기](/ko/guide/getting-started)

</div>
<div class="home-use-case">

### 여러 프로젝트에 같은 번역 {#one-set-of-translations-for-many-projects}

여러 패키지의 문서를 관리한다면 저장소마다 같은 번역 객체를 복사하지 말고 프로젝트마다 플러그인을 설치하세요. 번역을 고치면 다음 패키지 업데이트로 모든 사이트에 반영됩니다.

[사용 중인 프로젝트 보기](/ko/introduction#where-is-it-used)

</div>
<div class="home-use-case">

### 읽는 사람의 언어로 검색 {#search-in-the-reader-s-language}

`searchProvider`를 `local`이나 `algolia`로 지정하세요. 검색 버튼과 검색 창이 페이지 언어를 따라 바뀌고, 직접 지정한 `searchOptions`도 그대로 남습니다.

[검색 설정하기](/ko/guide/options#searchprovider)

</div>
<div class="home-use-case">

### 기존 폴더 이름 그대로 {#existing-folder-names}

이미 `eng`, `kor` 같은 폴더를 쓰고 있다면 파일 이름을 바꾸지 말고 폴더마다 언어 코드를 연결하세요. 기존 URL이 그대로 유지됩니다.

[폴더 연결하기](/ko/guide/options#locales-required)

</div>
<div class="home-use-case">

### 나중에 언어 추가 {#adding-a-language-later}

한 언어로 시작하고, 페이지 번역이 끝나면 다른 언어를 더하세요. `locales`에 코드를 넣고 폴더를 만들면 인터페이스 문구는 이미 번역되어 있습니다.

[언어 코드 확인하기](/ko/guide/supported-languages)

</div>
<div class="home-use-case">

### VitePress Sidebar와 함께 {#together-with-vitepress-sidebar}

이 사이트는 사이드바를 VitePress Sidebar로, 인터페이스 문구를 VitePress I18n으로 만듭니다. `withI18n`을 먼저 호출하고 그 결과를 `withSidebar`에 넘기세요.

[함께 쓰는 설정 보기](/ko/guide/getting-started#combining-with-other-plugins)

</div>
</div>
