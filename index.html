Features at a glance ​

The VitePress default theme shows its interface in English until you translate every label yourself. VitePress I18n adds those labels for each locale you list, so a Japanese page never ends with an English "Next page" link.

  • 13 languages built in English, Korean, Simplified and Traditional Chinese, Japanese, Spanish, Portuguese, Russian, Indonesian, German, French, Vietnamese, and Italian.
  • One function call Wrap your existing config with withI18n. There are no translation files to create or keep in sync.
  • Search is translated too The local search and Algolia DocSearch get their button, dialog, and empty-result text in each language.
  • Your wording wins Set label or a per-locale themeConfig, and your text replaces the built-in translation for that locale. title, description, and head can differ per locale as well.
  • Any folder layout Map folders such as eng or kor to language codes with { path, locale } and keep your current URLs.
  • lang and labels set for you Each locale gets its lang attribute, such as ko-KR, and its native name in the language menu.
  • Zero dependencies A small ESM package with no runtime dependencies. It runs once while VitePress loads your config.
  • TypeScript types VitePressI18nOptions and I18nLocale ship with the package under vitepress-i18n/types.

From one config to every language ​

Pass your VitePress options and the language codes you need. withI18n returns a config whose locales block already holds the translated interface text, and VitePress uses it on every page of that language.

Your config ​

js
// .vitepress/config.mjs
import { defineConfig } from 'vitepress';
import { withI18n } from 'vitepress-i18n';

const vitePressOptions = {
  title: 'My Docs',
  lastUpdated: true,
  themeConfig: {
    editLink: {
      pattern: 'https://example.com/edit/:path'
    }
  }
};

export default defineConfig(
  withI18n(vitePressOptions, {
    // Any of the 13 supported language codes
    locales: ['en', 'ko', 'ja'],
    searchProvider: 'local'
  })
);

Any VitePress site that publishes in more than one language can use VitePress I18n. Here are some typical setups.

Multilingual documentation sites ​

Keep one folder per language and list the language codes. The navigation labels, page footer, outline, and 404 page follow the language of each folder.

One set of translations for many projects ​

If you maintain docs for several packages, install the plugin in each one instead of copying the same translation objects between repositories. A translation fix reaches every site with the next package update.

Add it to your VitePress site ​

Install the package as a dev dependency, then wrap the object you pass to defineConfig with withI18n.

sh
npm i -D vitepress-i18n
sh
yarn add -D vitepress-i18n
sh
pnpm i -D vitepress-i18n
